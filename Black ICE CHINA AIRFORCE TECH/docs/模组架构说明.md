# 中系飞机科技树 —— 模组架构说明

> 这份文档写给「要往里加飞机/改布局/换文件夹名」的人。
> 一句话原则：**只有 `_tools/build/data_chi.py` 是手写的，其它游戏文件都是生成物。**

---

## 1. 文件职责

| 路径 | 手写/生成 | 职责 |
|---|---|---|
| `_tools/build/data_chi.py` | **手写** | 内容数据表：36 架飞机 + 22 发动机 + 11 枪炮 + 9 炸弹火箭 |
| `_tools/build/config.py` | **手写** | 全局常量：路径、文件夹名、国家标志、像素映射、年份布局 |

| `_tools/build/make.py` | 手写 | 一键构建入口 |

生成物全部带 `AUTO-GENERATED` 或由 make.py 覆盖；**手改会在下次构建时丢失**。

> `_tools/` 根目录下的 `scan_biad.py`、`probe.py`、`resolve_icons.py`、`arch_cats.py`、`dump_cands.py`、`cw_parse.py`
> 是立项阶段的一次性分析脚本（从 BIAD 抽取装备/模块/图标/分类清单），不参与构建，可以忽略；
> 日常只用到 `_tools/validate.py`、`_tools/install.ps1`、`_tools/verify_in_game.ps1` 和 `_tools/build/`。

## 2. 数据流

```
data_chi.py ──┬─> build_chi.py ──> CHI_air.txt
config.py  ──┤                   ├> technology_tags
              │                   ├> on_actions(flag)
              │                   ├> chi_air_technology.gfx
              │                   ├> countrytechtreeview.gui
              │                   ├> localisation/*.yml
              │                   └> descriptor.mod
              ├─> build_arrays.py ─> scripted_guis/BI_tech_queue_china_air.txt
              │                    ├> scripted_effects/…research_arrays.txt
              │                    ├> on_actions/…array_gen.txt
              │                    └> history/units/…generation.txt
              ├─> make_art.py ─────> techtree_china_air_tab.tga + thumbnail.png
              └─> make_preview.py ─> docs/科技树预览.png
make.py 负责按顺序跑上面四步，最后调 validate.py。
```

## 3. 加一架飞机（最常见的改动）

**只改 `data_chi.py` 的 `AIRFRAMES` 列表**，追加一个 dict：

```python
dict(
    key="p66",                                   # 科技 id = ad_chi_tech_p66
    equip="ad_vultee_p66_equipment_1",           # 必须是 BIAD 里真实存在的机体原型
    en="Vultee P-66 Vanguard", zh="伏尔梯 P-66 先锋",
    year=1942, x=26,                             # x=26 战斗机列；x 见 config.COLUMNS
    mfr="vultee_air",                            # 必须是黑冰 technology_categories 里的分类
    prev="p40e",                                 # 前置科技 key（同表内）
    desc_en="...", desc_zh="...",
),
```

然后：

```powershell
python _tools/build/make.py all
```

构建脚本会自动完成：

1. 从 BIAD 的机体原型读出 `ad_frame_config_*` 模块与 `archetype`，生成 `enable_equipments` / `enable_equipment_modules`；
2. 由 `archetype` 推出 `light_fighter` / `cas_bomber` / `tactical_bomber` 等分类；
3. 把 `prev` 展开成 `path.leads_to_tech` + `dependencies`；
4. 生成 `GFX_<tech_id>_medium`（复用该机体的图标）；
5. 在中英文里写入名称与描述；
6. 在 GUI 里加 `<tech_id>_tree` gridbox；
7. 在研究数组里写 `add_to_array` + `tech_x/y/cost/date` + `tech_dependents` 箭头；
8. 自动 `ai_create_variant` 块（让 AI 会造这型飞机）。

如果 `equip` 不存在、`x` 不在 `config.COLUMNS`、年份越界、`prev` 写错，构建会**直接中止并报错**。

### 加发动机 / 枪炮 / 挂载

同理，改 `ENGINES` / `GUNS` / `ORDNANCE`：

```python
dict(key="m105", x=4, year=1940, mfr="yakolev_air",
     en="Klimov M-105", zh="克里莫夫 M-105",
     modules=["ad_engine_sov_m105_1x"], prev="m62",
     desc_en="...", desc_zh="..."),
```

`modules` 里的每个 id 都会被校验是否在 BIAD 的模块表中存在；每项科技会自动带 `force_use_small_tech_layout`。

## 4. 改布局 / 换名字

| 想改什么 | 改哪里 | 连带注意 |
|---|---|---|
| 列的左右顺序 | `config.COLUMNS` + `data_chi` 里各条目的 `x` | 年标签位置在 GUI 里是固定 x=1700，列跨度太大时要一起调 |
| 年份范围 | `config.YEAR_BASE`（当前 1935，13 年） | 科技文件、GUI 年列、数组 `tech_date` 都会跟着变 |
| 文件夹名 | `config.FOLDER` | 同时改 `interface/countrytechtreeview.gui` 里容器名——**由 build_chi 自动生成**，无需手改；脚本里 `build_arrays` 也会跟着改 |
| 国家标志名 | `config.FLAG` | 会同步到 on_actions / technology_tags / scripted trigger |
| 哪些国家算中系 | `config.CHINESE_TAGS` | 影响标签页显示与 `air_techs_folder` 的隐藏条件 |
| 像素原点/行距 | `config.PIXEL_ORIGIN_X/Y`、`SLOT` | 直接影响黑冰科技页里图标的位置，改完要看实机 |

> 改名后务必重跑 `make.py all`，并检查 `validate.py` 的「folder wiring」「研究数组」两节。

## 5. 为什么需要「两层注册」

黑冰的科技页是**脚本界面**（`BI_research_scripted_gui.txt`）画的，不是原版 gridbox：

1. `scripted_guis` 的文件夹块负责「这个 folder 归哪个 window 管、点科技时调什么效果」；
2. 研究数组负责「这个 folder 里有哪些科技、每个科技摆在哪、多贵、哪年、指向谁」。

少任一层，表现都是**科技页空白且 error.log 不报错**——这是做黑冰科技模组最容易踩的坑。
本模组把两层都自动生成，`validate.py` 也会逐项检查。

---

## 5.5 一次性提示事件

新科技页第一次打开时，黑冰科研界面可能不画科技之间的连线（布局缓存）；存档再读档一次即可。
本模组用 `events/zz_CHI_air_tip.txt`（`CHI_air_tip.1`）在 `on_startup` 延迟 1 天弹一次，
并用 `CHI_air_tip_shown` 标志保证每存档只弹一次。开关在 `config.TIP_EVENT_ENABLED`。

## 6. 常见坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 科技页空白、无报错 | 缺 scripted GUI 块或研究数组 | 跑 `make.py arrays`，看 `system.log` 里数组是否注册 |
| 科技页空白 + 日志刷 `Found no grid box for tech` | `gridboxtype` 放错层级（放进了 `techtree_stripes` 之类的子容器） | 必须让 `gridboxtype` 成为 **folder 容器的直接子节点**；`validate.py` 已加层级检查 |
| 科研界面闪烁一下就打不开 + 日志刷 `Undefined GUI_TYPE: techtree_<folder>_item` / `Failed to create containerWindowType` | 缺少该文件夹的科技条目模板 | 复制一份 `techtree_<其它文件夹>_item` 与 `_small_item`，改名成 `techtree_<folder>_item/_small_item`，放在 guiTypes 顶层；`validate.py` 已检查 |
| 格子位置全挤在左上 | `tech_x/tech_y` 没写或全 0 | 检查数组文件里每项是否有 x/y |
| 科技能研究但不显示 | 缺 `GFX_<tech_id>_medium` | 校验器会报 missing icon |
| 图标问号 | sprite 注册了但贴图路径不存在 | 校验器会检查跨模组贴图存在性 |
| 启动器里看不到模组 | `.mod` 没放对目录，或 `path` 含中文 | 用 `_tools/install.ps1` 建 ASCII 联接 |
| 游戏里 `Active Mod Count` 不增加 | 同上：mod path 无法挂载 | 同上 |
| 中文显示成键名 | yml 缺 UTF-8 BOM 或语言头写错 | 生成器已写 BOM；手改 yml 时注意 |
| 游戏读档后标签页不出现 | 国家没有 `CHI_air` 且不是 CHI/PRC | `on_startup` 会挂标志；也可用 scripted trigger 查 |
| 与坦克子模互相覆盖界面 | 两个模组都覆盖 `countrytechtreeview.gui` | 本模组默认以坦克子模界面为底稿；不用坦克子模时换 `_install/countrytechtreeview.gui.biad_base` |

## 7. 验收命令

```powershell
# 全量构建 + 校验（0 error 才算过）
python _tools/build/make.py all

# 只看结构
python _tools/validate.py
```

校验覆盖：括号、id 冲突、坐标重叠、装备/模块/前置引用、分类合法性、中英文本地化、
图标 sprite 与贴图存在性、gridbox 一一对应、必需槽位可满足、依赖图无环、研究数组与 scripted GUI 注册。
